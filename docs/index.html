Human Activity Recognition

Can 2.56 seconds of phone sensor data tell what a new person is doing? We train classical models on the UCI HAR dataset and test them on 9 people the models never saw.

01

Research question

The question

Given a 2.56-second window of accelerometer and gyroscope readings from a phone worn at the waist, can we tell which of six activities a person is doing, if we have never seen that person before?

  • Walking
  • Walking upstairs
  • Walking downstairs
  • Sitting
  • Standing
  • Laying

Setup

One rowOne window: 128 readings at 50 Hz, overlapping the next window by 50%
TargetActivity label, 6 classes
When we predictAt the end of the window, using only the 561 features computed from that window
Main metricMacro-F1 (average F1 over the 6 classes), plus accuracy
Limits of the claimLab recordings, one phone model (Samsung Galaxy S II), 30 adults aged 19–48. We claim generalisation to new people in this setting, not to everyday life or other phones.

UCI Machine Learning Repository (Anguita et al., 2013), free to use and share under CC BY 4.0. 30 volunteers performed the activities in a lab with the phone on their waist. Quality checks

No missing values. All features were already scaled to [−1, 1] by the authors. 42 feature names appear more than once in features.txt, so we renamed the copies.

Two things that shape evaluation

Each person contributes 281–409 windows that overlap by 50%, so windows from one person are not independent. And 2,281 feature pairs have |correlation| > 0.95, so importance scores get split across near-copies.

Fit on training data only; 2,000 sampled windows. Moving and still activities separate clearly along PC1. The three still postures overlap in this 2D view, and sitting and standing overlap most. That overlap is where most errors end up later (the full models use all 561 dimensions, where laying separates well).

03

Preprocessing

1

Keep the people separate

We use the dataset's own split: 21 people for training, 9 different people for testing. No person appears in both. The test set is used once, at the very end.

2

Scaling inside a pipeline

Logistic regression, SVM and k-NN are sensitive to feature scale, so they get a StandardScaler. It sits inside a scikit-learn Pipeline, so it is re-fit on the training part of every CV fold and never sees validation or test data.

3

Nothing to impute

No missing values, so no imputation. The one thing we could not control: the authors scaled features to [−1, 1] before splitting, probably using all 30 people. It is a fixed linear rescale, so the effect should be small, but it is a mild leak we list as a limitation.

04

Baseline & methods

Every model was tuned with the same subject-grouped cross-validation (next section). Tuned values below are what the grid search picked.

Baselines

Two baselines: a floor and a simple model

Majority class always predicts the most common training class (laying): accuracy 18%, macro-F1 0.05. It is only a floor that shows the metric works.

8-feature logistic regression is the meaningful baseline: a small linear model on 8 hand-picked, easy-to-read features (movement intensity, phone tilt, rotation, frequency), tuned with the same grouped CV. It asks how far a few sensible features get before we use all 561. Answer: CV macro-F1 0.880, test 0.842.

The full models must beat the simple model, not just the floor, to justify using all 561 features. The same 8-feature model runs in the demo below.

Candidate

Logistic regression

A linear classifier: one weighted sum of features per class, then softmax. Tests whether the engineered features are already linearly separable, and its weights are easy to inspect.

Objective: minimise cross-entropy plus an L2 penalty. Assumes: each class's log-odds are a linear function of the features.

Grid: C ∈ {0.01, 0.1, 1, 10} → picked C = 0.1 (fairly strong regularisation)

Candidate

Random forest

200 decision trees on bootstrap samples, each split choosing from a random subset of features. Captures non-linear thresholds, copes with redundant features, needs no scaling.

Objective: each tree greedily picks splits that most reduce Gini impurity; the forest averages the trees. Assumes: classes can be carved out with feature thresholds, and the trees' errors are partly independent.

Grid: max_features ∈ {sqrt, 0.1}, min_samples_leaf ∈ {1, 5} → picked sqrt, 5 (min_samples_leaf = 5 is the largest value tried)

Candidate

SVM (RBF kernel)

Finds the boundary with the widest margin between classes; the RBF kernel lets that boundary curve. It is the method used in the original dataset paper.

Objective: hinge loss plus an L2 penalty (widest margin). Assumes: windows close together in scaled feature space usually share a class.

Grid: C ∈ {1, 10, 100}, γ ∈ {scale, 10⁻³, 10⁻⁴} → picked C = 100, γ = 10⁻⁴. Both are at the edge of the grid (largest C, smallest γ), so a wider grid might help the SVM slightly; see Limitations.

Candidate

k-nearest neighbours

No training: a window gets the majority label of its closest training windows. Checks whether "nearby in feature space" means "same activity" across people.

Objective: none to fit; it votes among neighbours. Assumes: Euclidean distance over 561 scaled features is meaningful, which gets harder as dimensions grow.

Grid: k ∈ {5, 11, 21, 41}, uniform/distance weights → picked k = 21, distance

Why these models

They span the main families: linear (LR), tree ensemble (RF), kernel/margin (SVM) and instance-based (k-NN). Deep learning on raw signals was out of scope; the features are already engineered, and the course rewards justified choices over complexity.

One assumption all of them make is that training windows are independent. They are not (overlapping windows from the same person), which is why we validate and estimate uncertainty per person.

05

Evaluation design

The protocol (fixed before comparing models)

  • Split the 21 training people into 5 groups; each CV fold validates on 4–5 people the fold's model did not train on (GroupKFold)
  • Tune every model's settings by grid search on this grouped CV
  • Pick the final model by CV macro-F1, before looking at the test set
  • Retrain on all 21 training people, then score the 9 test people once
  • Uncertainty: resample the 9 test people with replacement 2,000 times and recompute macro-F1 (a subject-level bootstrap)

Why macro-F1: it averages over activities, so a model cannot score well by being good only at the common classes.

Why grouping by person matters

The same tuned models scored with an ordinary random K-fold (windows shuffled) vs. our person-grouped K-fold. Random splits put the same person, and overlapping windows, in both training and validation.

Random K-fold overstates performance on new people by 5–8 points of macro-F1. An earlier version of this project used random K-fold, which is why its CV scores (~0.98) were far above its test scores.

Which model is best? Logistic regression had the highest CV score (0.934 vs. 0.932 for the SVM), so we selected it before testing. That lead is tiny next to the fold-to-fold spread (±0.04), so in CV the two effectively tie. On the test people the SVM scored slightly higher (0.956 vs. 0.950), but resampling the test people shows that gap is not reliable: the LR − SVM difference is −0.006 with a 95% interval of [−0.021, +0.003], which includes zero. We keep logistic regression: it is simpler, faster, and its weights can be read directly. All four full models beat the majority baseline by a wide margin. Against the simple 8-feature baseline, the full logistic regression is clearly better in CV (0.934 vs. 0.880) and on test (0.950 vs. 0.842), so the other 553 features add real information, not just complexity. k-NN, however, does not beat the simple baseline in CV (0.873 vs. 0.880): plain distance over all 561 features carries over poorly to new people.

What the interval can and cannot tell us: it shows how much the score depends on which people happen to be tested. It keeps the trained models fixed, so it ignores variation from which people were used for training, and with only 9 people its edges are themselves rough. It is not a formal significance test.

Train scores near 1.0 against CV ≈ 0.87–0.93 show every model fits the training people much better than new people. The gap looks like person-to-person variation rather than a tuning problem: changing a model's settings moves its CV score by about 0.02 at most, while changing which people are held out moves it by 0.08–0.13, and the same fold (people 14, 15, 19, 25) is the hardest for every model. The score of every setting and fold is in results/grid_search_results.csv. (k-NN with distance weighting scores 1.0 on train by construction.)

What the models rely on

Many features are near-duplicates, so a single feature's rank is unreliable: importance gets split between correlated copies. The by signal group view adds those copies up and is the more trustworthy one. This shows association with the label, not cause.

Errors & limitations

Which mistakes the selected model makes

Logistic regression gets 148 of 2,947 test windows wrong. The six most common mix-ups:

Sitting → standing alone is 39% of all errors. The stair errors come from walking activities that look alike over 2.56 s. Laying → standing (14 windows) is unusual: random forest and SVM classify every laying window correctly.

Errors depend on the person

Macro-F1 for each test person. Click a bar for details.

Subjects 10 and 9 account for 53% of all sitting/standing confusions.

A closer look at sitting vs. standing

The feature that best separates sitting from standing in the training data is tGravityAcc-max()-Y, which reflects how the phone is tilted relative to gravity. Below is where test windows fall on it. Toggle groups to compare.

The median wrongly classified sitting window (−0.105) sits on the standing side of the midpoint between the two correct groups (−0.078), and wrongly classified standing windows (−0.062) sit on the sitting side. So these errors are windows whose phone orientation genuinely resembles the other posture. A plausible cause is how upright a person sits or how the phone was worn, but the data cannot confirm that.

Limitations

  • Lab data, one phone, 30 adults. Everyday use (phone in a pocket or bag, other devices, older people) would likely be harder.
  • Only 9 test people. Scores move by several points depending on who is tested (see the intervals).
  • Pre-scaled features. The authors' [−1, 1] scaling was not fit on training data only.
  • Engineered features only. We did not try models on the raw signals.
  • Some best settings sit at the edge of their grid. SVM: C = 100 and γ = 10⁻⁴; random forest: min_samples_leaf = 5. These models may be slightly under-tuned, so our "logistic regression and SVM tie" conclusion is for the grids we searched. Changing settings moved CV scores by 0.02 at most, so we expect any gain to be small, but we did not test a wider grid.
  • No causal claims. Feature importance shows what the models use, not what causes an activity to be recognised.

What we would try next

  • Per-person calibration: a few labelled seconds from a new user might fix the sitting/standing offset.
  • Smoothing predictions over consecutive windows, since activities last longer than 2.56 s.
  • Testing on a free-living dataset to see how far the lab result carries.

09

Conclusion

  • For new people in this lab setting, a regularised logistic regression on the engineered features recognises the six activities with test macro-F1 0.950 (95% interval 0.915–0.976), against 0.05 for the baseline. Non-linear models did not reliably do better.
  • How you validate matters as much as which model you pick. Splitting by window instead of by person inflates scores by 5–8 points.
  • The remaining errors are mostly sitting ↔ standing, concentrated in two people, and caused by windows whose phone orientation looks like the other posture.
  • Phone orientation (gravity) features dominate what the models use; an 8-feature model already reaches 0.842.
  • We would not deploy this outside the lab without testing on free-living data and other devices.

Key decisions, explained by the person who made them

For each of us: one main choice and why we made it, how we checked it, one limitation, and what happens if you change one small thing. Every number here comes from analysis.ipynb.

Bhanavath Charan Tej Naik 25110073

My main choice Validate by person, not by window. Our first notebook used StratifiedKFold(shuffle=True) on windows. Windows overlap by 50% and each person gives 281–409 of them, so a shuffled split puts almost identical windows from the same person into both training and validation. The model is then tested on people it has already seen, which is not our question. I switched to GroupKFold with 5 folds by person, so every validation fold holds 4–5 people the model never trained on.
How I checked it I scored the same tuned models both ways. For logistic regression, shuffled K-fold gives 0.984 macro-F1 and grouped K-fold gives 0.934. The real test score on 9 new people is 0.950, much closer to the grouped number, so the grouped split is the honest one. The shuffled split overstated scores by 5–8 points for every model we checked. We picked the final model by the grouped CV score, before looking at the test set.
A limitation With only 21 training people, each fold has just 4–5 people, and the score moves by about ±0.04 from fold to fold. The top two models differ by only 0.002 in CV (0.934 vs. 0.932), so CV cannot really say which is better. We picked logistic regression but treat the two as a tie.
A small change What if we change C from 0.1 to 1? CV macro-F1 goes from 0.9339 to 0.9334: almost nothing. Across all four C values it moves by less than 0.01, and across all nine SVM settings by about 0.02. But changing which people are held out moves the score by 0.08–0.13, and one fold (people 14, 15, 19, 25) is the hardest for every model. So who you test on matters far more than the exact setting, and more tuning would not help much.

Prashant 25110245

My main choice Measure uncertainty by resampling people, not windows. Windows from the same person are strongly related, so treating the 2,947 test windows as independent would make the result look far more certain than it is. I resampled the 9 test people with replacement 2,000 times and recomputed macro-F1 each time. For logistic regression this gives 0.950, with a 95% interval of 0.915–0.976.

With so few people the interval edges are rough. The bootstrap also keeps the trained model fixed, so it ignores how much the result depends on which people we trained on.
